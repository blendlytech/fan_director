A · One-time step after a new sign-up

You’re signed in

One quick choice before you start planning. You can change it later in your account.

Rules for this state

  • Unticked + Continue writes nothing and goes where the fan was heading (the Director, Save or Send). Ticked + Continue goes to A2.
  • The wording is identical to design 16 A. The server records its version, plus source signup, time, IP and user agent. The browser never sends the wording.
  • The server decides whether to show the step. Showing it is not recorded in Clerk’s client-writable metadata.
  • If the fan leaves without pressing Continue, treat it as a skip. The step is not shown again; settings (design 16 A3) is where they opt in later.
  • Came from a page with no creator (for example the site home)? Don’t show the step. Opt-in is per creator, and there is no creator to ask about.

The checkbox stays ticked above this message, so Try again sends the same choice. Focus moves to this message.

A5 · Signed out before saving  ·  A6 · Already answered

You were signed out

Your choice wasn’t saved, so you’re not signed up for Maya’s news. Sign in again, then turn it on in your account if you’d like it.

Sign in again

The server returned 401 on save. Signing in again is an ordinary sign-in, so the step isn’t shown again; the message says where to opt in instead of promising the step comes back.

You’ve already chosen

You answered this in another window. You can change Maya’s news anytime in your account.

Continue Account settings

The server says the step is already done (a second tab, or Back after Continue). It doesn’t say which choice was made; settings shows the current state.

U1 · Unsubscribe link opened  ·  U2 · Done

Stop Maya’s news?

You won’t get news emails from Maya any more. Emails about your own requests and videos still arrive.

While sending: the button reads “Unsubscribing…” and is disabled.

You’re unsubscribed

You won’t get Maya’s news any more. Your account, Scene Cards and videos aren’t affected.

Same as design 16 A3. Subscribe again records a new consent row with source unsubscribe_page and the current wording, then shows “You’ll get Maya’s news again”.

Why a button, not “opening the link unsubscribes”: mail security scanners open links in emails automatically, which would unsubscribe fans who never clicked. Mail apps’ own one-click unsubscribe uses the List-Unsubscribe-Post header and needs no page at all. People who follow the link from the email body press one button, with no sign-in.

U3 · Bad or altered link  ·  U4 · Already unsubscribed  ·  U5 · Couldn’t unsubscribe

This link doesn’t work

It may be incomplete or changed. Nothing about your emails has changed. To stop the news, sign in and turn it off in your account.

Sign in

Signature check failed or the token is malformed. Same message for both, and it never names a creator or fan. No consent row is written.

You’re already unsubscribed

You aren’t getting Maya’s news, so there’s nothing to stop.

Valid link, latest row is already a withdrawal. Shown instead of U1 when the page loads, and also if Unsubscribe is pressed twice. Writes no duplicate row.

We couldn’t unsubscribe you

Something went wrong on our side, so you’re still subscribed for now. Please try again.

Server or database error with a valid link. Never show “unsubscribed” until the withdrawal row exists.

Not drawn here

  • Expired unsubscribe links: unsubscribe links don’t expire, because old emails must keep working. An expiry state would only teach Astra to add one.
  • Creator invitation and authenticator-app setup: Clerk’s hosted sign-up and account screens do these. If the Phase 1 build replaces them with custom screens, a design is needed first.
  • Sign-in network errors and rate limits: also Clerk-hosted screens.
